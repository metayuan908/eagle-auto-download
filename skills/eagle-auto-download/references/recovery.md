# 对账、共享素材与恢复

## 身份与项目关系

先查已保存的 Eagle ID 和提交响应 ID，再按目标库原件 SHA-256 查找；名称和项目 URL 只作辅助匹配，不能证明文件不存在。候选必须未删除且内容相符，随后核实目标文件夹。同字节对应多个 Eagle ID 时停止，不随意选择。HTTP 500、缺失原件或哈希不符均不能当成查无条目后重发。

Eagle 原件哈希验证先通过 API 核实活动库及条目身份，再只读该库中对应原件，拒绝符号链接和越界路径。不得用直接修改库内 metadata.json 或移动原件的方式修复数据。

一个 Eagle 条目只有一套名称、网址、注释、标签，可以属于多个项目文件夹。共享文件保持原条目元数据，不为新项目覆盖；项目简介写入项目文件夹，各项目来源及标签仍保留于本地记录。

`collection.shared_metadata_policy`：

- `review`（默认）：内容和关联核实后登记 `needs_metadata_review`，列出现有名称和来源，不算项目完成。
- `preserve_existing`：仅在用户接受共享条目保留原元数据后启用；核实原件、关联及文件夹简介后登记 `reused`。这不代表条目的名称、注释、标签已改成新项目内容。

已确认的策略可沿用，不反复询问。一次接受共享策略不代表授权覆盖其他条目的元数据。需要项目专属素材元数据时先生成受影响清单，不能靠重发文件解决。

## 提交与恢复

提交前将唯一 attempt_id、素材 ID、库路径、时间及是否重试落盘；返回 ID 立即保存，再回读。响应只含 success 时，轮询目标文件夹并在必要时刷新内容索引。文件和书签条目轮询均设置总截止时间，请求超时受剩余时间约束。

默认 `import --execute` 只对账 uncertain，找不到时保留原状态并继续其他独立记录。新提交的异常或验收失败停止当前批。用户明确要求重试时：

```sh
python3 <skill-dir>/scripts/collector.py --config <config> import --asset-id <asset-id>
python3 <skill-dir>/scripts/collector.py --config <config> import --execute --asset-id <asset-id> --retry-uncertain
```

只有新的全库核验仍无匹配时才重提，持久日志最多允许一次重提。重复调用不能重置计数，不手工删除日志或把 uncertain 改成 pending 来绕过。元数据待审核和原件验收失败均不能通过重发解决。多个 `--asset-id` 可重复；未知 ID、与项目范围冲突会在 API 写入前拒绝。

## 状态与完成判断

`status` 默认输出本地摘要；`status --details` 输出逐条原始状态。摘要不是对 Eagle 现状的实时审计。

| 状态或统计 | 含义 |
| --- | --- |
| imported | 文件或书签按当前项目规则验收完成 |
| reused | 共享条目按已接受的保留元数据策略完成关联验收 |
| needs_metadata_review | 文件已识别或关联，但共享元数据策略尚未接受 |
| uncertain | 提交结果或回读尚未核实，默认不重发 |
| represented_by_video | 原占位链接对应的视频已验收，记录替代 ID，不再作为下载待办 |
| awaiting_video | 占位链接仍无验收完成的视频，不能宣称文件完成 |
| fallback_bookmarks | 失败回退且已验收的链接，不计入视频文件 |
| accepted_unique_files | 按 Eagle ID 去重后的本地已验收文件数，与项目素材关系数不同 |

`summary` 为全队列；`scope_summary` 为本次项目范围，单条选择仍显示所在项目的完整完成程度。只有项目内没有真实待处理和 awaiting_video 才 complete；`preflight.ready` 仅说明离线条件允许执行。原占位链接的替代关系不会自动删除 Eagle 条目。升级版本也不代表历史内容已修复。

## 状态库兼容升级与性能

保留旧 assets/projects/settings 表；附加 files（库、哈希、Eagle ID）、project_links（项目归属与替代关系）及 attempts（提交/下载事件）。非空旧库首次扩展前在状态库旁 `state-backups` 创建 SQLite backup；不解除暂停，不开始下载或导入。按配置路径绑定导入队列，改用其他资源库时使用独立队列，不能复用旧 ID。

每批建立一次条目索引和文件夹树，已保存或返回 ID 优先定点回读；首次发现内容及显式恢复需要刷新时例外。指纹按路径、大小和修改时间缓存，项目简介按文件夹更新。报告输出 elapsed_seconds 和 api_metrics；不以提速为由跳过目标库、暂停、文件内容或元数据验收。

## 回归验收

更新时在隔离目录验证：跨项目同字节而名称/网址不同、共享元数据保护、成功响应含 ID 或不含 ID、响应丢失、最多一次重提、视频已导入但占位链接仍在、范围预检、重复失败事件、暂停及旧库备份。模拟接口通过后，按原有授权执行实际任务并回读；不能用实际导入当作 Skill 修改的自动测试。

Eagle 的 offset 行为按运行接口探测：首批 200 条后请求 offset=1，若其起点对应第二条则使用条目偏移；若完全无重叠则按页号继续。不能直接把 offset 加 200 当成通用规则。无法确认或后续页重叠时停止，避免漏掉已有素材。新提交刚返回 ID 时，条目索引短暂 500/503 可在原截止时间内继续轮询；旧条目出现相同错误仍不构成查无条目的证据。
